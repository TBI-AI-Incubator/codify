# Corpus storage API inventory

Design inventory, not implemented enforcement. Snapshot of the public storage APIs
at Core `9231311`. Enumerates every top-level non-underscore function with a `session`
parameter under `codify/storage`, including functions not re-exported by the package.
Private helpers inherit scope from their callers and must constrain every SQL operation;
renaming a public entry point does not exempt it. Pure parsing/formatting functions,
models and SQL-generation helpers without a session are outside this entry-point list.

The common strategy applies even to a UUID lookup, aggregate, cache, destructive
refresh or maintenance operation. Validate referenced ownership before writes and
retain database relationship constraints. Importing a submodule directly must not
provide an unscoped alternative. Optional foreign IDs and JSON identifiers need the
same validation; they cannot serve as evidence of ownership.

## Release gate

The implementation must turn this inventory into an executable check: enumerate these
session-taking functions in CI, classify any newly added function, and require an
explicit non-optional corpus parameter for every corpus operation. The metadata
exceptions above are an exact allowlist, not an exemption for the whole module.
Signature checks are necessary but do not prove query scoping: pair each classified
surface with owner, other-corpus, mixed-result and mutation tests on disposable data.
Review helper SQL, direct ORM use, public re-exports and caller-supplied pagination
predicates as part of those tests.

Outside storage, `codify/retrieve/hybrid.py` and any other session-taking Core entry
points must propagate scope; CLI, service and MCP handlers must select the authorised
corpus before invoking storage. Calling applications must also audit direct SQL and
ORM paths. A storage-only inventory cannot certify a complete application's boundary.

Do not enable multiple corpora or duplicate legal identities in a released runtime
while this inventory has unmigrated corpus operations. A partial implementation may
be tested in isolation, but it is not a deployable multi-corpus release. The final
migration and release checks must fail if the reviewed inventory, caller migration
or query/constraint acceptance evidence is incomplete. This is a required gate for
the implementation, not an existing automatic protection in this documentation PR.
